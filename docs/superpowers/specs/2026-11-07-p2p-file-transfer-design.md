# 点对点文件互传网站 — 设计文档

日期：2026-11-07
状态：已与需求方讨论确认

## 目标

做一个**完全零成本**运行的熟人文件互传网站：发送方创建房间、把房间码发给熟人，双方浏览器直接互传文件（含几十 GB 超大文件），服务器不经过文件数据。

## 非目标（明确不做）

- 不做离线暂存 / 发完即走（那需要服务器存储，违反纯 P2P 与零成本）
- 不做用户注册 / 账号体系
- 不做公开发布所需的限流、审计、内容合规
- 不承诺 100% NAT 穿透（零成本方案下约 80–90% 网络可直连，失败的兜底是提示换网络）
- 不做多人同时收发（一个房间 = 一收一发，一对一只做透）

## 场景与约束

- 使用人：熟人之间，双方同时在线
- 文件规模：单文件可达几十 GB；支持多文件队列、整文件夹
- 可靠性要求：断网 / 刷新 / 关浏览器后重开可断点续传
- 成本约束：零付费。域名、HTTPS、signaling、TURN 全部用免费方案
- 浏览器约束：完整体验以 Chromium（Chrome/Edge）为准；Firefox/Safari 的落盘能力受限，降级方案见下文

## 架构

```
┌─────────────┐         ┌──────────────────┐         ┌─────────────┐
│  发送方浏览器  │◄──────►│  PeerJS 公共撮合云 │◄──────►│  接收方浏览器  │
└──────┬──────┘  信令    └──────────────────┘  信令    └──────┬──────┘
       │                                                      │
       └──────────────► WebRTC DataChannel ◄───────────────────┘
                        （文件数据直连，不过服务器）
```

三个组成部分：

1. **前端 SPA**（Vite + TypeScript）：全部传输逻辑与 UI
2. **撮合（signaling）**：默认使用 PeerJS 公共云（免费、无需自己写后端）
3. **静态托管**：Cloudflare Pages / GitHub Pages 免费档，自带 HTTPS 子域名

升级路径（本次不实施，文档记录）：PeerJS 服务端是开源的单文件 Node 程序，未来可在 Oracle Cloud 永久免费虚机上自托管，前端只需改一个配置项。TURN 同理留配置开关，默认关闭。

## 配对设计

- 房间码 = 6 位大写字母+数字（去掉易混淆字符 0/O/1/I）
- 发送方点「创建房间」→ 以 `room-<房间码>` 为 Peer ID 连接撮合云，等待对方
- 接收方输入房间码 → 以随机 ID 连接撮合云，向 `room-<房间码>` 发起 WebRTC 连接
- 连接建立后双方通过控制通道握手，确认角色与版本

## 传输协议

两条 DataChannel：

- **控制通道**（有序可靠，JSON 消息）：文件元数据、接收进度位图、暂停/继续、完成确认、错误
- **数据通道**（每文件一条，无序 + 自定义确认，争取吞吐）：纯文件块，块头带文件 ID 与块序号

块格式（二进制，紧凑头）：

```
[4B 文件ID][4B 块序号][8B 块内偏移][块数据...]
```

- 块大小：64 KB 数据块（浏览器 DataChannel 消息的安全上限之上留余量）
- 背压：发送方监控 `dataChannel.bufferedAmount`，超过 16 MB 暂停切片，低于 4 MB 恢复，防止内存爆炸
- 确认：接收方每收一块在位图中置位，每 256 块（或 500 ms）通过控制通道回传一次进度位图

## 断点续传

- 接收方把每个文件的进度持久化到 IndexedDB：文件元数据 + 已收块位图
- 重开页面、重新输入房间码加入后：接收方上报已收位图，发送方只补发缺失块
- 发送方进度无需持久化（文件在发送方本地，天然还在）
- 同一文件（按 内容标识 = 名称+大小+最后修改时间 哈希）未完成时在接收方显示「继续接收」

## 接收落盘

- **Chromium**：File System Access API，接收前让用户选保存位置，块直接 seek 写入，全程不占内存
- **Firefox / Safari**：OPFS（各浏览器均支持）暂存，完成后提供「保存」；超大文件在这些浏览器上能力受限，UI 明确提示推荐 Chromium

## UI 设计

单页中文界面，三个状态：

1. **首页**：两个大按钮「创建房间」「加入房间」；加入时输入 6 位房间码
2. **房间页（发送方）**：房间码大字展示 + 复制 + 二维码（方便微信扫码）；拖拽文件/文件夹入队；队列项显示进度、速度、暂停/继续、取消
3. **房间页（接收方）**：等待发送方；收到文件列表后逐项显示进度；未完成的可「继续接收」

连接状态明确展示：等待对方 → 已连接 → 传输中 → 对方掉线（传输挂起，重连自动续）。

## 免费方案清单

| 项目 | 方案 | 费用 |
|---|---|---|
| 静态托管 | Cloudflare Pages 或 GitHub Pages | 0 |
| 域名+HTTPS | 平台免费子域名（如 `*.pages.dev`），自带 HTTPS | 0 |
| 撮合 signaling | PeerJS 公共云 | 0 |
| STUN | PeerJS 内置公共 STUN | 0 |
| TURN | 不配置；UI 在直连失败时提示换网络 | 0 |

## 测试策略

- Vitest 单元测试：分块器、背压控制器、进度位图、房间码生成/校验
- 手工联调：本地起两个浏览器窗口（localhost 属安全上下文，WebRTC 可用），走一遍收发、中途断网、刷新续传
- 构建产物 `npm run build` 必须通过

## 已知限制（写进产品 UI / 文档）

- 双方必须同时在线；发送方页面需保持打开直到对方下完
- 严格 NAT 网络下可能连不上，提示换网络或开手机热点
- Firefox/Safari 超大文件落盘受限
